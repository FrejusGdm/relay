# relay: prior art, positioning and pricing

Researched on 2026-10-07. Every claim below was read from the product's own site, its GitHub repository, its documentation or its release notes unless the text says otherwise. Where I could only find a secondary source (a blog, a search summary), I say so. This is research, not legal or tax advice.

A note on terms. A "harness" is a program that runs a model as a coding agent (Claude Code, Codex CLI, Cursor CLI, OpenCode). A "merchant of record" is a company that legally sells your product to the customer, so that it, not you, collects and pays sales tax and VAT. "Source-available" means you can read the code, but the license is not one the Open Source Initiative (OSI) approves as open source.

## 1. Products that sit above or around coding agents

### 1.1 What the founder's notes got right and wrong

**T3 Code (https://t3.codes, https://github.com/pingdotgg/t3code).** Verified.
- It describes itself as "the open-source control plane for coding agents" and lists Claude Code, Codex, Antigravity, OpenCode, Cursor and Grok. It is MIT licensed and free (license read from the GitHub API and the site; about 26,000 stars; the site says 24,000+ stars and "over 400,000 devs"). It ships desktop, web, iOS and Android clients. You bring your own subscription; the site says it resells no tokens.
- The claim that it can switch provider inside a thread is true, but with three caveats the notes did not mention. I read the release notes of the first Orchestrator V2 build (https://github.com/pingdotgg/t3code/releases/tag/v0.0.46-nightly.20261003.2610, published 2026-10-03):
  1. It is only in nightly builds. The latest stable release on 2026-10-07 is v0.0.45 (2026-10-02).
  2. The release notes warn in a boxed note: "Switching providers is supported, but it isn't the recommended way to use multiple harnesses. The handoff is lossy." The new provider gets a budgeted selection of the conversation's messages, but not the previous provider's reasoning, its tool calls and results, or attachments. T3 recommends a different feature instead, `delegate_task`, where one agent starts child agents on any provider and waits for their results (for example Claude planning, Codex implementing). Switching model within the same provider usually keeps the provider's own session.
  3. The notes said a pull request "was merged". The specific pull request I found for a portable handoff (https://github.com/pingdotgg/t3code/pull/14197) was closed on 2026-10-01 without being merged, because the maintainer wanted before and after screenshots and a recording. The feature did reach the Orchestrator V2 nightly, so the idea shipped, but I could not identify which pull request carried it.
- Other things V2 already does that overlap with relay's pitch: you can change "provider, account, model, or options between turns"; threads stopped by a usage limit show as "Limited" and can be resumed at reset or snoozed until reset ("Auto-resume when usage limits reset"); interrupted threads continue after a restart; scheduled tasks; a server-side message queue; an MCP server so agents can control threads. The stable app also has a usage view with limit countdowns per account.
- What T3 deliberately does not do: automatic failover across accounts. A user requested it (https://github.com/pingdotgg/t3code/issues/2471, closed as "not planned"). The maintainer replied that it is possible by adding two Claude providers, "but we are not sure how okay anthropic are with this so we're not encouraging it as a first party feature."
- How relay differs: T3 is a place where you chat with agents. Its handoff works only for threads that live inside T3. relay is a daemon underneath every client, so a job started in the Claude Code terminal can continue in Codex desktop and later be viewed in T3. relay's handoff is built from git checkpoints and an event log rather than a message transcript, so the working state (diff, tests, decisions) survives, which is exactly what T3 admits its handoff loses. The honest risk is that T3 is moving fast toward the same space (limits, resume, accounts, delegation) and it has the distribution.

**Get One (https://getone.one).** Pricing claim verified; the notes were slightly stale. I read the live page.
- What it is: a closed-source Mac app (plus iPhone app and a Linux server connector) that shows the status of your running agents in a toolbar, collects their questions into one Inbox, and routes what you type or say to the right agent. Its own FAQ says it is not a coding agent and does not act on its own. It requires agents to run inside herdr, a free open-source terminal for agents. The page does not state a license for One itself; I treat it as proprietary.
- Pricing, exactly as on the page today: Free is limited to 25 requests a day to One's own AI, reset at midnight UTC. Pro is $12.99 a month ($6.99 for the first month) or $119.88 a year (shown as $9.99 a month), after a 3-day free trial with a card. Lifetime is a "limited edition of 260", paid once, in five steps: $99 (sold out), $129 (sold out), $179 (on sale now, 32 left), $229, then $299 for the last 100. Lifetime includes "unlimited updates", uses your own API key, and has a 3-day full refund. The notes said "$99, $129, currently $179, rising to $229 and $299", which matches. The notes did not mention that the lifetime plan is capped at 260 units, or that the meta description now calls the app "free".
- Does it move work between providers or accounts? No. It shows and answers, it does not hand a job from one agent to another.
- How relay differs: One is about attention (who is waiting for me). relay is about continuity (the job keeps going when an agent stops). They are complementary, and One's pricing is the best direct comparison for a lifetime offer.

### 1.3 A policy risk that affects positioning (verified on Anthropic's page)

Anthropic's Claude Code legal page (https://code.claude.com/docs/en/legal-and-compliance) says OAuth sign-in is "intended exclusively for purchasers" of Claude plans and "designed to support ordinary use of Claude Code and other native Anthropic applications". It says developers building products that use Claude's capabilities, including those using the Agent SDK, "should use API key authentication", and that Anthropic does not permit third parties to "route requests through Free, Pro, or Max plan credentials on behalf of their users" or to "collect, store, or intermediate Claude.ai credentials or session tokens". It also says an end user may sign in to the unmodified Claude Code binary with their own subscription. The same page says plan usage limits "assume ordinary, individual usage".

What this means for relay (my reading, not legal advice): relay should only launch the unmodified official `claude` program inside a separate profile folder that the user signed into themselves, never read or store tokens, and say plainly that each account must be one the person legitimately holds. T3's maintainer avoided building account rotation for the same reason. I did not verify OpenAI's equivalent terms for Codex; that needs a check before launch. Secondary sources (blogs found by search) claim Anthropic bans people for rotating accounts, but I did not verify those against Anthropic's own pages, so I do not rely on them.

## 2. Licensing for an open-source tool with a possible paid layer

All details below were read from the license's own page or a reputable summary, with the examples verified on GitHub.

| License | What it allows | What it restricts | Real examples |
|---|---|---|---|
| **MIT** | Anything: commercial use, modification, redistribution, including closing the code in a product | You must keep the copyright notice. No warranty. No explicit patent grant and no trademark clause | T3 Code, Orca, CodexBar, ccusage, OpenCode, Crystal |
| **Apache 2.0** | Same freedoms as MIT | Must keep notices and mark changed files. Adds an explicit patent grant from contributors (ends if you sue over patents) and states it gives no right to use the author's names or trademarks (https://choosealicense.com/licenses/apache-2.0/) | OpenAI Codex CLI, Vibe Kanban, Emdash, Agent Orchestrator |
| **AGPL-3.0** | Free to use and modify | Anyone who runs a modified version as a network service must publish their source; derivative works must stay AGPL | Claude Squad |
| **Elastic License 2.0** | Use, copy, distribute, modify | Cannot be offered as a hosted or managed service; cannot remove or bypass license-key features. Not OSI open source | Superset |
| **Functional Source License (FSL)** | You can read, run, modify and redistribute it for almost any purpose, including internal commercial use | No "Competing Use": you cannot use it in a commercial product or service that competes with the licensor's. After two years each version converts automatically to Apache 2.0 (FSL-1.1-ALv2) or MIT (FSL-1.1-MIT) (https://fsl.software). Not OSI open source | Sentry and Codecov (relicensed in November 2023, per Sentry's post https://blog.sentry.io/introducing-the-functional-source-license-freedom-without-free-riding/); Liquibase Community 5.0 |
| **Business Source License (BSL 1.1)** | Source visible; non-production use free; the licensor can add an "Additional Use Grant" allowing some production use | Production use otherwise needs a commercial license. Converts to a GPL-compatible license on a Change Date, at most four years after release (https://mariadb.com/bsl-faq-adopting/). Every project writes its own terms, so each BSL is effectively a different license | MariaDB, HashiCorp Terraform (BSL since August 2023) |

What the history teaches (from search summaries of well-known events, not first-party pages, so treat as context): when HashiCorp moved Terraform from an open license to BSL in 2023, the community forked it as OpenTofu within weeks. Redis and Elastic both loosened their restrictions later by adding AGPL, but forks (Valkey, OpenSearch) had already attracted their communities. A license change after adoption costs trust.

Practical consequences for relay:
- Choosing MIT or Apache 2.0 for the core means anyone, including T3, a larger company or a cloud vendor, can copy the scheduler and sell it. The protection is then speed, brand and the paid layer, not the license.
- A source-available license (FSL) from day one blocks a direct commercial clone for two years but is not "open source", which some developers and companies refuse to use, and which will weaken the "open source" line on the landing page. T3, OpenCode, Orca and Warp (as of this research) compete partly on being open source.
- Apache 2.0 over MIT is the better choice for a tool that talks to many vendors' tools and may take outside contributions, because of the explicit patent grant and the clear trademark clause (which lets you protect the name "relay").
- The common, low-risk shape is: permissive open core (MIT or Apache) for the daemon, the CLI and the adapters, and a separate closed-source paid app or feature set (Pro). I found no first-party example in this category that put the scheduler core behind a paid wall, and the two shutdowns (Vibe Kanban, Terragon) show that free users alone do not fund the work.
- Decide the license before the first public release. Do not start permissive and tighten later (see HashiCorp).

## 3. Selling a lifetime license for local software

### 3.1 How comparable tools sell "lifetime"

The word "lifetime" means two different things, and the page should say which:
- **Perpetual license with a year of updates.** Proxyman (https://proxyman.com/pricing): $89 Standard (1 device) or $99 Personal (2 devices plus mobile), one-time, one year of updates, then you keep the final version forever. TablePlus (https://tableplus.com/pricing): $99 Basic or $129 Standard, perpetual, one year of updates, renewal $59 per device. Both offer a free trial or limited free version and a 7-day money-back guarantee (TablePlus).
- **Lifetime including all future updates.** Get One: $99, then $129, $179, $229, $299 across five steps, 260 copies, "unlimited updates" (see 1.1). The rising price creates urgency and rewards early believers, but promises updates forever for a product whose costs (keeping up with other companies' changing CLIs) never end.
- Raycast (https://www.raycast.com/pricing) and Linear (https://linear.app/pricing) use subscriptions instead: Raycast Free, Pro $10 a month or $96 a year; Linear Free, $10, $16 per user a month. Superset charges $15 to $20 a month, Conductor $50 a month. So the paid layers in this category are mostly subscriptions for cloud and team features, with the local app free. A paid lifetime license for a local developer tool is rarer, and Get One is the only one I found in this exact category.

### 3.2 Delivering a license key and checking it offline

What I verified:
- **Signed license files or keys.** Keygen documents offline licensing: a license file signed with Ed25519 or RSA that the app verifies locally, optionally encrypted, which can carry an expiry date, a grace period, a version entitlement and a machine ID (https://keygen.sh/docs/choosing-a-licensing-model/offline-licenses/). The app ships only the public key, so it can check a license without internet. Keygen's free tier covers up to 100 "active licensed users" and 10 releases, and it has no per-sale cut (https://keygen.sh/pricing/).
- **Online validation APIs.** Polar's validate endpoint is public and needs no secret, "safely used on a public client, like a desktop application", taking the key and your organization id; it supports activation limits and expiry (https://polar.sh/docs/api-reference/customer-portal/license-keys/validate, https://polar.sh/docs/features/benefits/license-keys). Lemon Squeezy has activate, validate and deactivate endpoints, rate limited to 60 requests a minute (https://docs.lemonsqueezy.com/help/licensing/license-api). I found no offline option in either of those two.
- **Paddle** does not generate keys in its current product. Per a Paddle-related search summary, Paddle Billing gives you no license key; sellers pair it with Keygen (https://keygen.sh/integrate/paddle/). I did not confirm this on Paddle's own pages.

A design that fits relay (my recommendation): the checkout provider sends a webhook after payment; a tiny server (or Keygen) signs a license token with an Ed25519 private key; the buyer receives it by email; the app checks the signature locally with the public key and optionally checks for revocation when online. The app must keep working when the network is down, because the product's whole purpose is surviving outages. Local checking is easy to bypass for a determined person, so keep the Pro features modest and the price low enough that paying is simpler than cracking. I could not verify how specific closed tools (for example Proxyman or TablePlus) implement their keys internally.

### 3.4 Donations and sponsorships, and the rule about never calling a license a donation

- **GitHub Sponsors** (https://docs.github.com/en/sponsors/getting-started-with-github-sponsors/about-github-sponsors): no fee on sponsorships from personal accounts; up to 6% on organization sponsorships (3% card processing plus 3% GitHub fee). One-time and monthly. Payouts through Stripe Connect in many countries, and a manual route elsewhere. GitHub notes sponsorships "are generally not tax deductible but can be in some cases" (https://docs.github.com/en/sponsors/sponsoring-open-source-contributors/about-sponsorships-fees-and-taxes).
- **Polar** can also take recurring sponsorships and one-time contributions (pay what you want), so the same account can hold both Pro sales and donations if kept as separate products.
- **Why a license must never be called a donation** (my reasoning, supported by the facts above): a donation is voluntary and gets nothing in return. A license is a sale, because the buyer receives a right to use software. Calling a sale a donation misleads the buyer (who may think it is tax deductible or optional), confuses the tax treatment (a sale carries sales tax or VAT; a gift usually does not), and breaks the merchant of record's rules (Paddle forbids donations; a merchant of record collects tax on sales). It also muddies the open-source message: the free product must stay free to everyone, and sponsors must not get more than recognition unless that is described as a purchase. Practical rule: use the words "Buy Pro" and "price" for licenses, use "Sponsor" only for GitHub Sponsors or a separate Polar sponsorship product, and keep them in two separate places on the site.

### Patterns that read as generic AI design (my judgment, grounded in the CSS above)

- **Default Tailwind palettes.** Zed and Conductor both use Tailwind's stock grays (#101828, #364153, #6a7282, #99a1af, #d1d5dc, #e5e7eb), Tailscale uses Tailwind's gray scale in OKLCH, and T3 Code and Superset use Tailwind's zinc and neutral (#09090b, #a1a1aa, #71717a; #171717, #fafafa). Superset's variables are the stock shadcn names (--primary, --accent, --foreground). When the palette is the framework default, the page looks like a template.
- **Inter plus zinc dark plus one blue or indigo accent plus a monospace for every label.** Used by T3, Superset, Warp and many others. Linear's indigo #5e6ad2 and Tailwind's #6366f1 (Warp) are everywhere because AI tools copy Linear.
- Other tells to avoid, seen on typical AI-built pages (not specifically verified on the sites above): glowing gradient blobs behind the hero, three equal feature cards in a row, emoji or generic stroke icons as feature art, "10x" and "supercharge" claims, fake logo walls, a floating terminal screenshot that shows no real product state, and uppercase monospace eyebrow labels over every section.
- What the best pages do instead: a custom or unusual typeface (Resend's serif, Raycast's serif accent, Cursor's serif, Get One's Aeonik), a warm rather than cold neutral (Conductor, Cursor, Warp, Bun), exactly one accent used rarely, real product UI as the main image, and copy with a point of view.

## Top five insights for relay's positioning and pricing

1. **The "run many agents in parallel" space is crowded and has already produced shutdowns; the continuity space is not crowded.** More than ten tools run agents in parallel worktrees (Conductor, Superset, Orca, Emdash, Claude Squad, Vibe Kanban, Agent Orchestrator). Two of them have died or pivoted (Vibe Kanban in April 2026, Terragon in February 2026, Crystal into Nimbalyst). Nobody I found hands a job's state from one provider or account to another in a way that keeps the working state. Position relay as "your job keeps going when an agent stops", never as another agent manager.
2. **T3 Code is the neighbour to design around, not against.** It already switches provider in a thread, resumes at limit reset and tracks per-account usage, but its own release notes call the switch "lossy" and recommend delegation instead, and its maintainer declined account rotation over Anthropic policy worries. relay's honest edge is a handoff built from git checkpoints and an event log that works for any client (terminal, desktop apps, T3), plus rollback. Say that, and avoid claiming that nobody does cross-provider switching.
3. **Money in this category comes from cloud and team features, not from the local tool.** Conductor ($50 a month cloud), Superset ($15 to $20 a month), Raycast and Linear all keep the individual local product free. The one lifetime offer I found, Get One, runs a capped, rising-price lifetime plan on a product with its own hosted AI. For relay, a free open core plus a one-time Pro for local power features is plausible, but expect most users to stay free, which is exactly what ended Vibe Kanban.
4. **If you sell "lifetime", define it.** The tried-and-true shape is a perpetual license with one year of updates (Proxyman $89 to $99, TablePlus $99 to $129). The riskier shape is lifetime with all updates forever (Get One), which is hard to afford because relay's adapters need constant repair as Claude Code, Codex and Cursor change. A rising early-bird price with a visible count builds urgency honestly if you really limit the copies.
5. **Account handling is the policy risk that can sink the product.** Anthropic's page forbids third parties from routing requests through subscription plans or storing credentials. Design relay so each account is signed in by the user, through the official unmodified CLI, in its own profile folder, with no token handling by relay, and write that into the landing page and README. Say "accounts you legitimately hold", and keep "bypass limits" language out entirely.

## Decisions only the founder can make

1. **License of the core:** MIT, Apache 2.0, or FSL (source-available with a two-year conversion). My lean is Apache 2.0 for the core and a closed Pro app, but it depends on whether "open source" is a promise you are willing to keep forever.
2. **Whether to charge at all in version 1,** and what Pro would contain (for example automatic failover, multi-machine, dashboard) versus what stays free (manual switch, checkpoints, rollback).
3. **What "lifetime" means:** perpetual with 12 months of updates, lifetime of one major version, or lifetime with all updates; whether to cap the number of copies and raise the price in steps as Get One does.
4. **Payment provider and where the business is registered:** a merchant of record (Polar, Lemon Squeezy, Paddle, Stripe Managed Payments) versus Stripe alone. This depends on the founder's country and legal status, which I do not know. Also whether to use Polar's built-in license keys or sign your own offline tokens.
5. **How to treat multi-account support,** given the policy text above: how much to say publicly, and whether to ask Anthropic and OpenAI directly (Anthropic's page invites questions through its sales contact) before launch.
6. **Donations:** whether to open GitHub Sponsors or a Polar sponsorship product at all, and committing to keep it separate from Pro.
7. **Name and brand look:** whether the landing page follows the warm, editorial direction (serif accent, warm neutral, one accent color) or the dark developer default. The research suggests the warm path is the one that stands out.
8. **Relationship with T3:** compete, integrate (adapter plus a relay panel inside T3), or both. This changes how you talk about T3 on the site.
