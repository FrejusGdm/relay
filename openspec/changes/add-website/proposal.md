# Proposal

## Why

relay needs a public page that says what it does and how to install it. Josué approved building the website from the design preview (`docs/design/preview.html`) and hosting it on Azure Static Web Apps in his own subscription (`docs/ROADMAP.md`, "Decisions made", 2026-10-07; the private task board, queue item 12). The preview already holds the page's content and look, but it also holds the preview's own controls (headline, font, accent and theme pickers, a token reference), loads fonts from Google Fonts and Fontshare, keeps choices in `localStorage`, and has spacing that breaks at phone width. This change turns it into a small static site that can be deployed safely, and adds the one thing the preview lacks: a working "CLI setup" panel with the real install commands.

## What Changes

- Add the website source in `site/public/`: `index.html`, `styles.css`, `site.js`, `theme.js`, `404.html`, `robots.txt`, `favicon.svg` and `staticwebapp.config.json`. They are plain HTML, CSS and JavaScript with no build step and no framework: the deployed files are the files in the repository. Source: `docs/design/preview.html`; `DESIGN.md` ("Motion": plain CSS animation, no motion library).
- Port the preview's page (hero with the handoff card, the providers row, "Switching agents by hand costs you the afternoon", "Everything the next agent needs", "One agent or a hundred", the closing panel and the footer) and remove everything that exists only for the preview: the top bar with its pickers, the token reference section, the motion demos, the headline variants and the `localStorage` code. The page uses the choices Josué already made: Satoshi headlines, olive accent, the headline "Never run out of limits again." (`DESIGN.md`, change log). The navigation has one theme button that switches between Light and Dark, with Light as the default (item 4).
- Polish the spacing (design decision 6): section spacing inside the 96 to 144 pixel range that `DESIGN.md` sets, a shorter time scale in the "by hand" timeline, background track lines that never cross text, and illustrations that fit their cells at phone width. The page must fit at 1440, 1024 and 390 pixels wide with no horizontal scroll, which Playwright checks.
- Add the "CLI setup" panel. The "CLI setup" and "Get relay" buttons open one panel with the exact commands to install the command-line tool on macOS (Apple silicon) and Linux (x64) from the private repository's GitHub Releases with `gh release download`, each with a copy button. The Mac app block shows a "not released yet" note until a release contains `Relay-macOS.zip`. The panel says plainly that the repository is private for now and that `gh` must be signed in with access to `FrejusGdm/relay`. Source: `docs/ROADMAP.md` ("License: Apache 2.0. The repository stays private for now; releases are installed with `gh`"); GitHub CLI manual for `gh release download`.
- Add a short pricing section that matches the business decision: the core is free, and paid features will come later as a one-time payment for a lifetime license. The page shows no price, no checkout and no payment form; payments are a separate later change (the private task board, queue item 13). Source: `docs/ROADMAP.md` ("Business model", 2026-10-07); `docs/research/prior-art-and-pricing.md` section 3.1 and insight 4 ("If you sell lifetime, define it", which is why the page does not define it yet).
- Self-host the three typefaces. Public Sans and IBM Plex Mono come from their official GitHub releases (SIL Open Font License); Satoshi comes from Fontshare's download (ITF Free Font License, which allows self-hosting on your own website but not redistribution through a repository). A script downloads them and checks each file's SHA-256; the font files are not committed. Source: the licenses inside each download, read on 2026-10-07.
- Lock the page down with a strict Content-Security-Policy and security headers in `staticwebapp.config.json`: only same-origin scripts, styles, fonts and images; no inline script or style; no network requests from the page; no framing. No telemetry, no third-party scripts or trackers, no cookies, and no browser storage except the theme choice. Static Web Apps' built-in sign-in routes are turned off. Source: `docs/research/security.md` section 9 ("Telemetry": none); `openspec/config.yaml` ("No telemetry"); Microsoft Learn, "Configure Azure Static Web Apps".
- Host the site on Azure Static Web Apps, Free plan, in "Azure subscription 1", in one resource group `relay-rg`, with every resource tagged `project=relay`. Create the app with `az staticwebapp create` and no GitHub connection. Deploy from the Omarchy machine with the Static Web Apps CLI (`swa deploy`), passing the deployment token through the `SWA_CLI_DEPLOYMENT_TOKEN` environment variable read straight from `az staticwebapp secrets list`, so the token is never printed, written to a file or copied by hand. Source: `docs/ROADMAP.md` ("The website: deployed to Azure Static Web Apps"); Microsoft Learn, "Deploy a static web app with Azure Static Web Apps CLI" (https://learn.microsoft.com/en-us/azure/static-web-apps/static-web-apps-cli-deploy, checked 2026-10-07); Azure CLI reference for `az staticwebapp` (https://learn.microsoft.com/en-us/cli/azure/staticwebapp, checked 2026-10-07).
- Add tests: `bun test site/test` checks the files (no external resources, no inline script or style, no storage or network code, the exact headers, the exact install commands, the pricing copy), and Playwright checks the page at 1440, 1024 and 390 pixels wide, the panel and its copy buttons, and the absence of console errors and Content-Security-Policy violations. Add a smoke test of the live address (HTTP 200, the page title, the install command, the headers, no cookie) and Playwright screenshots of the live site at the three widths.
- Add `docs/website.md` (how the site is built, tested and deployed, with diagrams), a `site/` row in `README.md` and in the codebase map, and update the "What deploys on merge" and "Website hosting" pins in the private task board.

## Decisions pending Josué's decision

Approving this proposal approves the recommendations below.

1. **Keep search engines away until the public release. Pending Josué's decision.** Recommendation: serve `X-Robots-Tag: noindex, nofollow` and a `robots.txt` that disallows everything, and do not announce the address. Two decisions that `docs/ROADMAP.md` lists as open block "public release, marketing": asking Anthropic and OpenAI directly, and the name. A live but unindexed page lets Josué share the link without making the public launch decision early. Removing the header and changing `robots.txt` is a one-line change later.
2. **No links that lead nowhere. Pending Josué's decision.** Recommendation: remove the preview's "GitHub" and "View source" links and the footer links "Changelog", "Security", "Email" and "Report a problem", because the repository is private (a visitor without access gets a GitHub 404 page) and the other pages do not exist. The closing panel's second button becomes "CLI setup". The footer keeps "How it works", "Pricing", "CLI setup" and a link to the Apache 2.0 license text. `DESIGN.md` asks for approval before deviating from the preview, hence this item.
3. **Headline weight. Pending Josué's decision.** `DESIGN.md` says Satoshi 700 to 900 for headlines, but the preview, which Josué approved by eye, renders headlines at weight 500. Recommendation: keep the preview's 500, because the website is built from the preview. The site loads Satoshi's variable font, so either weight works without another download.
4. **Theme.** Josué asked on 2026-10-08 for the light version and a switch after seeing the live site; the site now offers Light, Dark and System, with Light as the default. Josué then asked on 2026-10-08 for one icon button with only Light and Dark, like ChatGPT's, in place of the three buttons.
5. **Region. Pending Josué's decision.** Recommendation: `eastus2` for the resource group and the app. The Free plan serves static files from a global network, so the region mostly decides where Azure keeps the resource's metadata.
6. **Mac app first launch.** `docs/ROADMAP.md` says the unsigned Mac app is opened the first time with right-click, Open. Since macOS 15 (Sequoia), right-click Open no longer opens an app that Gatekeeper blocks; the person must click "Open Anyway" in System Settings, Privacy & Security (Apple Support, "Open a Mac app from an unknown developer", https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac, checked 2026-10-07; Macworld, https://www.macworld.com/article/2457844/what-to-do-when-you-cant-open-an-app-you-just-installed-in-macos-sequoia.html). A zip downloaded with `gh` is not marked as downloaded from the internet (only apps such as browsers add that mark), so Gatekeeper does not check the app at all. Recommendation: the panel gives the `gh` commands, and tells people who downloaded the zip in a browser to use "Open Anyway". The decision row in `docs/ROADMAP.md` should be corrected the same way when this proposal is approved.

## Security

This change adds a public web page and a deployment credential, and it tells visitors how to download and run software.

- **The deployment token.** Static Web Apps accepts a deployment by anyone who holds the app's deployment token. The deploy script reads it with `az staticwebapp secrets list` into a shell variable and passes it to `swa deploy` through `SWA_CLI_DEPLOYMENT_TOKEN` for that one command. It is never printed, never written to a file, never committed and never stored in GitHub. The script never runs with `set -x`, never passes `--print-token` or `--verbose=silly` (the two ways the CLI prints the token, checked in its source, `src/cli/commands/deploy/deploy.ts`, version 2.0.10), and checks that the deployment output does not contain the token. If the token ever leaks, `az staticwebapp secrets reset-api-key --name relay-site --resource-group relay-rg` replaces it. Source: Microsoft Learn, "Deploy a static web app with Azure Static Web Apps CLI", section "Deployment token" ("Don't store deployment tokens in a public repository").
- **No GitHub connection.** The app is created without `--source`, so Azure creates no workflow file in the repository, no repository secret and holds no GitHub token.
- **Azure sign-in.** The Azure CLI on the Omarchy machine is already signed in. This change stores no new Azure credential and no service principal. Every Azure command names the subscription "Azure subscription 1" and the resource group `relay-rg`, and the scripts refuse to run when the Azure CLI uses another subscription. The scripts set `AZURE_CORE_COLLECT_TELEMETRY=false` for their own commands, without changing Josué's Azure CLI settings.
- **Browser security.** The Content-Security-Policy allows only the site's own scripts, styles, fonts and images (`default-src 'none'`), no inline script or style, no network requests (`connect-src` falls back to `'none'`), no forms and no framing. The site sets no cookie. Its only browser storage is the theme choice: `theme.js` keeps `light` or `dark` in one `localStorage` entry, `relay-theme`, which never leaves the browser because the page makes no network requests. Every storage call is inside `try`, so the page still works when the browser blocks storage. A test checks that `theme.js` uses no other storage and no network, and that `site.js` uses no storage at all. Static Web Apps' built-in sign-in routes under `/.auth/` answer 404, because the site has no sign-in. Source: `docs/research/security.md` section 9 (no telemetry); Microsoft Learn, "Configure Azure Static Web Apps" (global headers, routes, response overrides).
- **Supply chain.** The page loads nothing from other servers. Fonts are downloaded by a script that checks each file's SHA-256 before it is used. The Static Web Apps CLI is run with an exact version (`@azure/static-web-apps-cli@2.0.10`) on the Omarchy machine only; it checks the SHA-256 of the deployment program it downloads (`src/core/download-binary-helper.ts`). `@playwright/test` is pinned to an exact version as a development dependency. Source: `docs/research/security.md` section 8, recommendation 6 (few dependencies, pinned).
- **The install commands.** They download release files with `gh`, signed in, over HTTPS, from the one repository `FrejusGdm/relay`. They never pipe a download into a shell, never use `sudo` and install into the person's own `~/.local/bin`. `gh release download` does not verify a checksum or an attestation; adding `gh attestation verify` belongs to the release change and the public release (`docs/research/security.md` section 8, recommendation 4). The Mac app instructions never tell the person to turn Gatekeeper off.
